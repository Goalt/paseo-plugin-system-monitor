# ТЗ: плагин Paseo «system-monitor» — загруженность системы во времени

Версия: 1.1 — **утверждено заказчиком 2026-09-08** (ответы на §10 внесены в текст).

## 1. Цель

Trusted-плагин для Paseo 0.6.1, показывающий в сайдбаре загруженность сервера во времени:
CPU, RAM и диск — текущие значения плюс исторические графики с переключаемым окном
(1 час / 24 часа / 7 дней). Сбор метрик и хранение истории — на стороне демона; клиент
только отображает.

## 2. Что именно измеряется (проверено на живом окружении)

Демон Paseo работает в контейнере ai-dev-agent, но cgroup-лимитов нет (`memory.max = max`,
`cpu.max = max`), поэтому `/proc` отдаёт метрики **всего хоста VPS**:

| Метрика | Источник | Проверенное значение |
|---|---|---|
| CPU % | дельта агрегатной строки `/proc/stat` | 12 ядер |
| RAM | `/proc/meminfo`: `MemTotal`, `MemAvailable` | 47 ГиБ всего, ~22.6 ГиБ доступно |
| Диск | `fs.statfs` по списку путей, по умолчанию `["/"]` | `/` = хостовый `/dev/sda1`, 387 ГБ, 36% |

Это фича, а не баг: пользователь видит загруженность всего сервера. Зафиксировать в README.

Формулы:
- CPU% = 1 − (Δidle + Δiowait) / Δtotal по агрегатной строке `cpu`.
- RAM% = (MemTotal − MemAvailable) / MemTotal (не по `free`, чтобы не пугать page cache'ем).
- Disk% = (blocks − bfree) / blocks по statfs; плюс абсолютные used/total.

## 3. Ограничения платформы (обязательные, демон 0.6.1)

Наследуются из проекта kanban-board — все проверены на практике:

1. Точка входа `index.ts`; компилятор вырезает `plugin.handle(...)` из client-бандла и
   `addSurface`/`addSidebarItem` из server-бандла. Только ExpressionStatement-вызовы.
2. Клиентские импорты: `react`, `react/jsx-runtime`, `react-native`, `@tanstack/react-query`,
   `zod`, `@getpaseo/plugin`. **Никаких chart-библиотек** — графики рисуем View-примитивами.
3. **В клиентском коде запрещены `async`/`await`** (компилятор 0.6.1 не понижает синтаксис —
   плагин молча не появится на iOS/Android). Только промис-цепочки.
4. Имена RPC — только `^[a-z][a-z0-9._-]*$` (camelCase роняет весь плагин).
5. Палитра темы: только `surface0`, `foreground`, `foregroundMuted`, `accent`,
   `accentForeground`, `statusDanger`. Нет `warning`, нет `border`.
6. Push из RPC нет — клиент поллит через TanStack Query `refetchInterval`.
7. State-файл — в `$HOME`, не в каталоге плагина (server-бандл исполняется через
   `globalThis.eval`, `__dirname` отсутствует).
8. `contribute()` обязан вернуть cleanup: `clearInterval` всех таймеров + финальный flush
   state-файла, иначе reload плагина плодит осиротевшие сэмплеры.

## 4. Функциональные требования

### 4.1 Сбор метрик (server)

- Сэмплер стартует в `contribute()`: CPU и RAM — каждые **5 с**, диск — каждые **60 с**
  (меняется медленно).
- Три кольцевых буфера с даунсэмплингом (avg + max на бакет):

| Ряд | Шаг | Ёмкость | Окно |
|---|---|---|---|
| fine | 5 с | 720 | 1 час |
| hourly | 1 мин | 1440 | 24 часа |
| daily | 15 мин | 672 | 7 дней |

- Бакет хранит `{ ts, cpuAvg, cpuMax, ramAvg, ramMax, disk }` (disk без max — не осциллирует).
- Персистентность: `~/.paseo-system-monitor.json`, запись раз в 60 с и в cleanup.
  История переживает reload плагина. Оценка размера: ~2832 бакета ≈ 300–400 КБ — ок.
  Рестарт демона теряет максимум 60 с истории.
- При ошибке чтения `/proc`/statfs — сэмпл пропускается, ошибка в `console.error`
  (видна в `paseo plugin logs`), сэмплер не падает.

### 4.2 RPC (contract.ts, общий файл)

| Имя | Вход | Выход |
|---|---|---|
| `sysmon.snapshot` | — | текущие CPU%, RAM (%, used/total байт), диск `/` (%, used/total), uptime хоста, cores |
| `sysmon.history` | `{ window: "1h" \| "24h" \| "7d" }` | массив бакетов соответствующего ряда |

Два RPC достаточно; meta (cores, totals) кладём в snapshot.

### 4.3 UI (сайдбар-сурфейс «System monitor», иконка `Activity`)

- **Тайлы текущих значений** (сверху): CPU%, RAM% + абсолют, Disk% + абсолют.
  Значение ≥ 90% — цвет `statusDanger`, иначе `foreground`. (Промежуточного warning в
  палитре 0.6.1 нет — двух состояний достаточно.)
- **Переключатель окна**: 1ч / 24ч / 7д (сегмент-кнопки, активная — `accent`).
- **Три графика** (CPU, RAM, Disk) — бар-чарт из `View`-примитивов: ряд флекс-колонок,
  высота = avg бакета, тонкая «шапка» сверху до уровня max. Бары с avg ≥ 90% — `statusDanger`,
  остальные `accent`. Подписи времени: начало / середина / конец окна, `foregroundMuted`.
  Вертикальная ось значений (доработка по ревью 08.09): подписи 0–100% слева (шаг 25%,
  в compact — 50%) + горизонтальные гридлайны `foregroundMuted` с прозрачностью.
- **Тап по бару** → строка под графиком: время бакета, avg, max (ховера на мобильном нет).
- Автообновление: snapshot — раз в 5 с, history — раз в 15 с; поллинг промис-цепочками
  по паттерну docker-containers (`useState` + `setInterval`), таймеры чистятся при анмаунте.
- Состояние «нет данных» (первый запуск, окно ещё не накоплено) — graceful: рисуем что есть.
- Ошибка RPC → плашка «нет связи с сэмплером» + последние полученные данные (паттерн kanban-board).
- Обе темы (light/dark), `layout.compact` для мобильной вёрстки.

### 4.4 Вне скоупа v1 (кандидаты в v2)

- Разбивка по контейнерам / процессам (это уже есть в docker-containers).
- Алерты при превышении порогов (правильный механизм — Paseo schedule, не плагин).
- Сеть и iowait как отдельные графики.
- Настройка списка маунтов через UI (v1: константа в contract.ts, по умолчанию `["/"]`).

## 5. Архитектура файлов

```
~/paseo-plugins/system-monitor/
  paseo-plugin.json        # { "id": "system-monitor" }
  index.ts                 # contribute(): сэмплер, plugin.handle × 2, addSurface/addSidebarItem
  monitor.client.tsx       # сурфейс: тайлы, переключатель, три графика
  contract.ts              # zod-схемы snapshot/history + константы (пороги, окна, маунты)
  docs/SPEC.md             # этот файл
```

Эталон паттернов: `~/paseo-plugins/docker-containers` (структура, промис-хелперы,
вырезание server-кода) и `kanban-board` (state-файл, плашка потери связи).

## 6. Нефункциональные требования

- Накладные расходы сэмплера: < 0.5% CPU (чтение двух файлов `/proc` раз в 5 с — копейки).
- Никаких shell-команд в горячем пути: только `node:fs` (`readFile`, `statfs`). Нет
  пользовательского ввода, попадающего в команды.
- `npm run typecheck` чистый; плагин `running` в `paseo plugin ls` без ошибок.
- Плагин обязан работать в браузере, Electron и на мобильном клиенте (значит — п. 3.3).

## 7. Риски

| Риск | Митигация |
|---|---|
| 720 баров в ряд — тяжело для RN-рендера | Рендерим ≤ 120 баров: клиент схлопывает бакеты под ширину; при `layout.compact` ≤ 60 |
| Появление cgroup-лимитов у контейнера в будущем исказит «хостовые» метрики | Зафиксировано в README; v2 может читать cgroup при `memory.max ≠ max` |
| Рестарт демона чистит state? | Нет: файл в `$HOME` вне жизненного цикла плагина; теряется ≤ 60 с |
| Рассинхрон часов бакетов после простоя демона | Дыры в истории отображаем пустыми барами, не интерполируем |

## 8. План работ (после одобрения ТЗ)

Kanban-проект `system-monitor` (правило каталога). Два спринта, приёмка каждого — демо-видео
(CDP-screencast, паттерн kanban-board):

- **Спринт 1**: скелет плагина, сэмплер + кольцевые буферы + персистентность, оба RPC,
  тайлы текущих значений. Видео №1: живые цифры, обновление раз в 5 с, обе темы.
- **Спринт 2**: три графика, переключатель окон, тап по бару, схлопывание баров, состояния
  «нет данных»/«нет связи», compact-вёрстка. Видео №2: полный проход + reload плагина
  с сохранением истории.

## 9. Критерии приёмки

1. `paseo plugin ls` → `system-monitor running`; typecheck чистый.
2. Тайлы совпадают с `top`/`free`/`df` на хосте в пределах погрешности (±2 п.п.).
3. График 1ч заполняется в реальном времени; после `paseo plugin reload` история на месте.
4. Переключение 1ч/24ч/7д мгновенно (данные уже на клиенте либо один RPC).
5. Обе темы: ни одного чёрного текста на тёмном фоне; все цвета из `theme.colors`.
6. Компакт-режим: панель читабельна на мобильной ширине.
7. Убийство сэмплера невозможно штатно: ошибка чтения метрик логируется и пропускается.

## 10. Решения ревью (заказчик, 2026-09-08)

1. Окна — 1ч/24ч/7д, без 30 дней.
2. Мониторим только `/`.
3. Порог подсветки — 90%.
4. loadavg-тайл не нужен: только CPU/RAM/Disk.
